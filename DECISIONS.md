# Технические решения (DECISIONS)

Ключевые развилки миграции прототипа `course-app_2.html` в полноценное
приложение. Формат: решение → причина.

## 1. Основа проекта
**Решение:** строим на уже существующем проекте Next.js 16 (App Router) + React 19 +
TypeScript + Tailwind v4, а не скаффолдим заново.
**Причина:** проект уже настроен, современный и Vercel-совместимый; переиспользуем.

## 2. База данных и ORM — РЕАЛИЗОВАНО (Drizzle + PGlite/Postgres)
**Решение:** ORM — **Drizzle**. Драйвер выбирается по `DATABASE_URL` в `src/lib/db.ts`:
- локально (пусто или не `postgres://`) → **PGlite** (Postgres в WASM, в процессе Node,
  данные в `./.pglite-data`) — без Docker и без сервера;
- прод (`DATABASE_URL=postgres://…`) → **postgres-js** к обычному Postgres.
Диалект один (PostgreSQL), код запросов общий. Таблицы создаются идемпотентно
(`ensureSchema`, CREATE TABLE IF NOT EXISTS) — без drizzle-kit-миграций.
В БД — только пользовательские данные: `users`, `lesson_progress`, `quiz_attempt`,
`detective_attempt`. Контент курса остаётся в JSON (read-only, SSG) — намеренное
отклонение от TASK.md (контент как код быстрее и не ломает статику).
**Причина смены Prisma→Drizzle:** `npm install prisma` виснет на докачке движка
Prisma; Docker Desktop не стартует. Drizzle+PGlite — pure-JS/WASM, ставится за секунды,
работает локально без инфраструктуры, деплоится на любой Postgres сменой `DATABASE_URL`.
**Прод:** на купленном сервере поднять Postgres, задать `DATABASE_URL=postgres://…` —
код и схема не меняются.

## 3-auth. Аутентификация — РЕАЛИЗОВАНО (своя сессия, не Auth.js)
**Решение:** email+пароль. Пароли — bcrypt (`bcryptjs`), сессия — подписанный JWT
(`jose`) в httpOnly-cookie (`src/lib/auth.ts`). API: `/api/auth/{register,login,logout}`,
`/api/me`. Гость читает уроки/глоссарий/калькуляторы без входа; прогресс гостя в
localStorage, при входе автоматически переносится в аккаунт (`/api/progress/import`).
**Причина (вместо Auth.js):** next-auth v5 — beta с частыми ломающими изменениями;
своя реализация на pure-JS `jose`+`bcryptjs` надёжнее в этом окружении, деплоится
куда угодно и полностью под контролем. Отклонение от TASK.md зафиксировано здесь.
Прогресс идёт через единый провайдер `src/lib/progress.ts` (БД для залогиненных,
localStorage для гостей) — страницы/компоненты его не различают.
**Жёсткий гейт (`src/middleware.ts`):** разделы курса (/study, /lesson, /module,
/quiz, /detective, /glossary, /calculators) доступны только с валидной сессией
(проверка JWT через jose в Edge); гость → 307 на `/login?next=<путь>`. Публичны:
/, /login, /register, /api/auth/*. `/api/mentor` тоже требует вход; виджет наставника
скрыт у гостей. После входа AuthForm возвращает на `?next=`.

## 9. ИИ-наставник (Gemini через SOCKS5-прокси)
**Решение:** наставник реализован. Персона перенесена из прототипа
(`src/lib/mentor-prompt.ts`), подставляется контекст текущего урока. Серверный
`/api/mentor` вызывает Gemini (`generativelanguage.googleapis.com`) **через SOCKS5-прокси**
(`node:https` + `socks-proxy-agent`), т.к. Gemini недоступен с части IP. Виджет-чат —
на всех страницах (`MentorWidget`), урок определяется по URL.
**Секреты — только в `.env.local` (в .gitignore), не в коде:**
- `MENTOR_PROXY_URL=socks5://…` (проверено: TLS-over-SOCKS5 работает, IP меняется);
- `GEMINI_API_KEY=` — **нужно вписать свой ключ** (https://aistudio.google.com/apikey);
  без ключа наставник отвечает понятным сообщением-подсказкой;
- `MENTOR_MODEL=gemini-flash-latest`.

## 3. Аутентификация
**Решение:** Auth.js (NextAuth v5) — Credentials (email + пароль, хеш bcrypt) +
Prisma-адаптер, JWT-сессии.
**Причина:** минимум из TASK.md (email+пароль). OAuth можно добавить позже без
переработки. JWT-сессии проще для гостевого доступа и edge-совместимости.

## 4. Продающий лендинг vs обзор курса  ← отклонение от TASK.md
**Решение:** `/` — **продающая страница** курса (оффер, результаты, тарифы), без
раскрытия модулей. Обзор курса/приложение (то, что TASK.md называет `/`) перенесён
на **`/study`** и доступен всем (гостям — для чтения, залогиненным — с прогрессом).
**Причина:** пользователь явно потребовал, чтобы первая страница продавала курс и НЕ
показывала, что внутри модулей. Обзор с 15 модулями противоречил бы этому, поэтому
он живёт на отдельном маршруте.

## 5. Дизайн  ← смена относительно первой версии
**Решение:** светлая профессиональная тема прототипа: акцент green `#1F7A3D` /
`#175C2E`, фон `#FCFCFB`, карточки `#FFFFFF`, бордер `#E5E7EB`, радиус 12px,
системный шрифт. Ранняя тёмная «премиум» тема заменяется.
**Причина:** TASK.md предписывает визуальное соответствие `course-app_2.html`, и
пользователь выбрал полную миграцию по TASK.md. `course-app_2.html` — источник истины
по UX.

## 6. Источник контента
**Решение:** контент извлекается из встроенных в `course-app_2.html` блоков
`<script type="application/json">` (course-data, quiz-data, detective-data) и JS-массива
глоссария скриптом `scripts/extract-content.mjs` → `prisma/data/*.json`, затем seed в БД.
Копия `course-app_2.html` хранится в репозитории (`docs/source/`) для воспроизводимости.
**Причина:** отдельных JSON-файлов (`full_content.json` и т.п.) в наличии нет — данные
только внутри HTML.

## 7. Калькуляторы
**Решение:** формулы перенесены 1-в-1 из прототипа в `src/lib/calculators.ts`
(NPV, IRR методом бисекции, WACC, CAPM, точка безубыточности + DOL, LTV/CAC,
цена облигации, уравнение Фишера). Логика клиентская, БД не нужна.
**Причина:** формулы уже проверены в прототипе — переносим, не переписываем заново.

## 8. Вне скоупа
- ИИ-наставник (`mentor-backend/`) — не интегрируем; оставляем место под `app/api/mentor/`.
- Платежи — заглушка (CTA «Записаться»), подключение позже.
- Админка контента — контент правится через seed/БД, не через UI.
